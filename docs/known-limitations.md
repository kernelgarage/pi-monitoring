# Known limitations

- **No per-container Docker resource metrics (cAdvisor).** This was attempted and removed twice. The blocker: hosts using the containerd-snapshotter storage backend (`docker info` → `driver-type: io.containerd.snapshotter.v1`, the Docker 29.x default) break cAdvisor's per-container metadata lookup (`failed to identify the read-write layer ID`) — every `container_*` panel shows no data regardless of cAdvisor version. There's a workaround (point cAdvisor at `/run/containerd/containerd.sock` with `--containerd-namespace=moby`), but it only surfaces containers by raw container-ID hash rather than name, and drops Compose labels entirely — not worth the trade. The real fix (disabling the containerd snapshotter in `/etc/docker/daemon.json` and restarting Docker) is a host-wide storage-backend change with real downtime risk if the host runs anything else, so think carefully before doing it just for a dashboard. Bottom line: **you get host-level CPU/memory/disk from `node-exporter`, but not a per-container breakdown**, without accepting one of the above trade-offs.
- **Nothing feeds Tempo out of the box.** It's provisioned and ready to receive traces (`OTEL_EXPORTER_OTLP_ENDPOINT=http://tempo:4317` from any app on the `monitoring` network), but no app in this repo emits any until you point one at it.
- **No alerting.** No Alertmanager or Grafana alert rules are configured — nothing pages on error-rate spikes, host issues (temperature/throttling), or service downtime.
- **Tempo is pinned to `2.8.1`**, not `latest` — `latest` currently resolves to an unreleased v3.0 rewrite with an incompatible config schema (compaction moved to a separate backend-scheduler architecture). Check `tempo/tempo.yaml` compatibility before bumping.
- **Dashboards you build in the Grafana UI** (as opposed to JSON files dropped in `grafana/provisioning/dashboards/json/`) live only in Grafana's own database (`./data/grafana/grafana.db`) and won't be tracked anywhere in this repo unless you export their JSON model (*Dashboard settings → JSON Model*) and commit it yourself. The Grafana admin password is also set by hand on first login — there's no env var for it.
- **Other apps join this stack from the outside.** The `monitoring` Docker network is defined here (non-external) so this stack must be `up` before any external Compose project that joins it with `external: true` can start.
